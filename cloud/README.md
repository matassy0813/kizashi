# Kizashi クラウド同期サーバー

チームで同じプロジェクトを見るための、小さな同期サーバーです。Cloudflare Workers と Durable Objects（中にSQLiteのデータベースを持つ）で動きます。Firebase や Supabase などの外部データベースは使いません。

## 仕組み：運営者（開発者）にも顧客の情報が読めない

- **データの暗号化**：プロジェクトのデータは、ブラウザの中で「プロジェクト鍵」（ランダムな256ビット鍵、AES-GCM）を使って暗号化してから送ります。
- **鍵の預け方**：プロジェクト鍵は、メンバーごとに「本人のパスワードから作った鍵」（PBKDF2-SHA256、60万回）で包んで預けます。
- **パスワードの扱い**：パスワードそのものは、サーバーに届きません。サーバーが受け取るのは、パスワードから作った確認用の値だけで、保存するのはさらにそのハッシュです。
- **サーバーにあるもの**：暗号化されたデータ、包まれた鍵、確認用の値のハッシュ、ログインIDと役割、だけです。サーバーやデータベースを直接見られる運営者でも、中身は読めません。
- **同時に保存したとき**：版番号が合わない書き込みは `409` で断ります。ブラウザ側で両方の変更を項目ごとに合わせてから書き直します（`js/merge.js`）。
- **ほかの人への知らせ**：書き込みがあると、ログイン中の人に WebSocket で「新しい版がある」とだけ知らせます。
- **ログイン失敗**：10回続けて間違えると、そのIDは15分間ログインできません。セッションの期限は30日です。

## アカウント（最初の画面のログイン／新規登録）

- 1人1つのアカウント（ログインIDとパスワード）で、参加しているプロジェクトをまとめて開けます。
- アカウントには「アカウント鍵」があり、本人のパスワードから作った鍵で包んで預けます。
- 参加しているプロジェクトの鍵の一覧（キーリング）は、アカウント鍵で暗号化して預けます。サーバーは中身を読めません。
- 各プロジェクトへは、キーリングにあるプロジェクトごとのランダムな合言葉で入ります（パスワードを聞き直さない）。

| 操作（`/api/v2/account/<操作>`） | 内容 | 権限 |
|---|---|---|
| `POST signup` | アカウントを作る（ID・確認用の値・包んだアカウント鍵・暗号化したキーリング） | だれでも（新しいIDのみ） |
| `GET exists?login=` | IDが使われているか | だれでも |
| `POST prelogin` / `POST login` | 塩を受け取る／ログインして、包まれたアカウント鍵とキーリングを受け取る | だれでも |
| `GET keyring` / `PUT keyring` | キーリングの受け取り・更新（版番号が合わなければ `409`） | 本人 |
| `POST password` / `POST logout` / `DELETE me` | パスワード変更・ログアウト・アカウント削除 | 本人 |

## API（v2：プロジェクト）

`/api/v2/p/:id/<操作>`。ログインが必要なものは `Authorization: Bearer <セッション>` を付けます。

| 操作 | 内容 | 権限 |
|---|---|---|
| `POST create` | プロジェクトを作る（PMのID・確認用の値・包んだ鍵・暗号化データ） | だれでも（新しいIDのみ） |
| `POST prelogin` | ログインIDの塩（salt）を受け取る | だれでも |
| `POST login` | 確認用の値を送り、セッションと包まれた鍵を受け取る | だれでも |
| `GET me` / `POST logout` / `POST password` | 自分の状態・ログアウト・パスワードの設定 | 本人 |
| `GET doc` / `PUT doc` | 暗号化データの受け取り・保存（`{ver, blob}`、版番号が合わなければ `409`） | メンバー |
| `GET members` | メンバーの一覧（ID・役割・招待中か） | メンバー |
| `PUT member` | 招待（新規）・招待のやり直し（案内コードで入り直す） | PM・PMO |
| `PATCH member` | 役割の変更 | PM・PMO（PMの役割はPMのみ） |
| `DELETE member?login=` | ログインを止める | PM |
| `DELETE project` | プロジェクトを消す | PM |
| `GET ws?t=<セッション>` | 新しい版の知らせ（WebSocket） | メンバー |

以前のリンク共有方式（v1：`/api/p/:id`）は、切り替えのために残しています。

## 公開のしかた

公式の同期サーバーは `https://kizashi-cloud.kizashipm.workers.dev` で動いていて、アプリの既定になっています（`js/cloud.js` の `CLOUD_DEFAULT`）。サーバー側（このフォルダ）を直したら、リポジトリの直下で次を実行して公開し直します。

```bash
npx wrangler@4.157.0 deploy --config cloud/wrangler.toml
```

自社でサーバーを立てる場合は、Cloudflare の無料アカウントで `npx wrangler@4.157.0 login` のあと上のコマンドを実行し、アプリの「設定・データ」→「チームで共有」→「同期サーバー」にそのURLを入れます。

## 手元で試す

```bash
npx wrangler@4.157.0 dev --config cloud/wrangler.toml --port 8787 --ip 127.0.0.1
```

結合テストは `tests/cloud-it.js` にあります。アプリを開いた状態で読み込み、`await runCloudIT('http://127.0.0.1:8787')` を実行します。

## 注意

- **アプリのコードの信頼**：Webアプリなので、ブラウザで動くコード（GitHub Pages の Kizashi.html）を信頼することが前提です。ソースコードは公開しています。気になる場合は Kizashi.html を自社で置いて使えます。
- **手元のPCの控え**：ログイン中は、そのPCのブラウザにデータの控えと鍵があります。ログアウトすると消えます。
- **1つのプロジェクトの大きさの上限**：暗号化・圧縮したあとで約1.9MBです。
